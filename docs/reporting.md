# Reporting

Spreadsheet based reports of different datasets for both UK (CDS) and XI (Taric) tariffs are generated on a nightly basis.

These are generated within this application using workers scheduled to run on Sidekiq in the morning after the daily synchronisation of tariff data has occurred.

After generate, these files are uploaded to our Reporting S3 bucket.

These reports are generated daily on both UK and XI backend services, with the exception of Differences report, which is UK only and only generated on Mondays.

## Manual regeneration

Regeneration of these files can be manually triggered from the UK and XI backends using a dedicated rake task - which will trigger running the worker job.

```
# bundle exec rake reporting:generate_daily_reports
```

## Differences report

There is a separate report, referred to as the differences report or sometimes the 'potential issues report'

It is generated by a separate worker which triggers only on Mondays on the UK service, and is triggered 30 minutes after the completion of the UK daily reports. This delay is to both XI and UK have completed daily report generation.

It works by downloading CSVs of relevant data for both UK and XI from the Reporting bucket and generating an XLSX highlighting differences between the two.

**This report is emailed automatically to HMRC.**

It can be manually triggered on any day using a rake task

```
# bundle exec rake reporting:generate_differences_report
```

To generate without emailing the report to HMRC use the following

```
# bundle exec rake reporting:generate_differences_report NOEMAIL=true
```

## Search reference changes report

A CSV of every search reference change (create, update and delete) in the previous calendar month. The rows come from the paper trail `versions` table.

`SearchReferenceChangesReportWorker` runs on both UK and XI at 10:30 UK time on the first Monday of each month. It generates the CSV, uploads it to the Reporting bucket and emails it with the CSV attached.

**This report is emailed automatically** to `SEARCH_REFERENCES_REPORT_TO_EMAILS` (a comma-separated list or a Secrets Manager JSON hash). The support email is BCC'd. No email is sent if the variable is not set.

The email and CSV use the same layout as the search reference invalidation alert that `ClearInvalidSearchReferences` sends. Automatic removals are grouped as Missing, Expired, Superseded and Unknown. These are followed by Added, Updated and Manually deleted.

When `ClearInvalidSearchReferences` removes a search reference, it stores the removal reason and successor IDs in the `metadata` column of the destroy version. The report uses this stored snapshot. It does not work out the reason again from the current tariff data, so later tariff corrections do not change the section, and the report agrees with the original alert. Removals that have no stored reason are shown as Unknown. These are removals made before the column existed, and backfilled destroy versions.

Each line uses `SearchReferences::ChangeLineFormatter`. The CSV has a readable "Source" column (for example "Automatic clean-up", "FPO CSV import" or "Admin user") and the raw "Changed by" value (the admin user UID or the job name). The email groups all admin users as "Admin users", with a count for each UID. The labels are in `SearchReferences::ChangeSource`.

Titles and whodunnit values come from users, so the CSV serializer uses `escape_formulas!`. Any text cell that starts with `=`, `+`, `-`, `@`, a tab or a carriage return (after optional spaces) gets a leading `'`, so spreadsheet tools show it as text and do not run it.

Technical operators can generate the report, with or without the email, from the admin Reports page. They can also download today's file there.

## Code

The code used to generate the various reports is held under [app/lib/reporting](https://github.com/trade-tariff/trade-tariff-backend/tree/main/app/lib/reporting) with different reports following a common pattern of `Reporting::<ReportName>.generate`

The actual reports generated by each of the workers can be seen in the relevant workers, see

* [Daily Reports Worker](https://github.com/trade-tariff/trade-tariff-backend/blob/main/app/workers/report_worker.rb)
